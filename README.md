# ETF 动量轮动策略回测

在四只 ETF 的真实历史前复权日线上，完整重放一套「动量轮动 + 波动率目标 + 绝对动量避险」策略，并以**单文件网页**的形式展示回测结果。

交付物就是一个 HTML 文件 —— 双击用浏览器打开即可，**不需要服务器、不需要装依赖、断网也能用**（ECharts 与行情数据都已内联）。

> ⚠️ **本项目是历史回测，全部结果均为对过去的模拟，不构成任何投资建议。**
> 回测中的"零成本""按收盘价成交"等假设在实盘中不成立，请勿据此决策。

## 策略是什么

**标的池**（四只，覆盖权益、债券、商品三类资产）：

| 代码 | 名称 | 上市 | 角色 |
|---|---|---|---|
| 513100 | 纳指ETF | 2013-05 | 权益 / 海外 |
| 511260 | 十年国债ETF | 2017-08 | 债券 |
| 518850 | 黄金ETF | 2020-06-05 | 商品 |
| 510300 | 沪深300ETF | 2012-05 | 权益 / 境内 |

**规则**：

| 规则项 | 定义 |
|---|---|
| 调仓时点 | 每周五收盘；周五休市则顺延到该自然周最后一个交易日 |
| 动量信号 | 当日收盘价 ÷ N 个交易日前收盘价 − 1（各 ETF 用自身交易日序列；N 默认 25） |
| 切换规则 | 四只中动量最大者全仓持有 |
| 并列处理 | 最大值**不严格大于**当前持仓的动量时，保持原持仓（避免无谓换手） |
| 避险 | 最强动量 < 0 时全仓转为国债 ETF（511260） |
| 波动率目标 | 按策略近期已实现波动缩放仓位，未用满的部分放国债；关闭则始终满仓 |
| 成交价 | 当日收盘价成交 —— 信号与成交同价，**无前视偏差** |
| 成本 | 切换时按比例扣减（默认 0.1%），可设为 0 |
| 回测区间 | 四只数据齐备之日（2020-07-10）起，至数据末日 |

| 配置 | 总收益 | 年化 | 夏普 | 最大回撤 | 卡玛 | 溃疡指数 | 马丁比率 |

## 指标口径

所有口径都在页脚有对应说明，实现于 `engine.js` 的 `computeMetrics()`。

| 指标 | 公式 | 方向 |
|---|---|---|
| 总收益率 | 期末净值 / 期初净值 − 1 | 越大越好 |
| 年化收益率 | (1 + 总收益)^(252 / 交易日数) − 1 | 越大越好 |
| 夏普比率 | (日均收益 − 日无风险利率) / 日收益标准差 × √252 | 越大越好 |
| 最大回撤 | 日频净值相对历史峰值的最大跌幅 | 越小越好 |
| 当前回撤 | 当前净值相对历史峰值的跌幅 | 越小越好 |
| 卡玛比率 | 年化收益 / 最大回撤 | 越大越好 |
| 溃疡指数 | √(Σ DDᵢ² / n)，DDᵢ 为每个交易日的回撤深度 | 越小越好，0 = 从未回撤 |
| 马丁比率 | (年化收益 − 无风险利率) / 溃疡指数 | 越大越好 |
| 年化波动率 | 日收益标准差 × √252 | — |
| 周度胜率 | 周收益 > 0 的周数占比 | 越大越好 |

溃疡指数同时惩罚回撤的**深度**与**持续时间**，是比最大回撤更全面的痛苦度量；马丁比率可理解为"以溃疡指数为分母的夏普"。

## 项目结构

> 🔴 **`ETF动量轮动回测Pro.html` 是构建产物，不要直接改** —— 任何直接修改都会在下次构建时丢失。要改就改 `app-pro.html`，再跑 `build_pro.py` 重建。

### 交付物与源码

| 文件 | 说明 |
|---|---|
| `ETF动量轮动回测Pro.html` | **交付物**（单文件，约 1.4MB，构建产物） |
| `app-pro.html` | Pro 页面源码 —— 界面、渲染、自动更新逻辑 |
| `ETF动量轮动回测.html` | 旧版页面（基准策略，构建产物），保留作对照与回归 |
| `app.html` | 旧版页面源码 |

### 核心逻辑

| 文件 | 说明 |
|---|---|
| `engine.js` | 回测引擎 + 指标计算。纯函数、无 DOM 依赖，浏览器与 Node 双端可跑 |
| `data.js` | 内嵌行情（含 `dividends` 分红表）。⚠️ 有**两条**顶层语句：`var ETF_DATA = {...}` 和 `ETF_DATA.extended = {...}` |

## 开发流程

```bash
cd etf-rotation-backtest

# 1. 改源码（不是改交付物！）
#    app-pro.html  → 界面/图表/参数/自动更新
#    engine.js     → 回测与指标逻辑
#    data.js       → 行情（应由 rebuild_data.js 生成）

# 2. 重建单文件版
python3 build_pro.py

# 3. 重生成引擎结果（必须在 verify.py 之前）
node run_engine.js

# 4. 双实现交叉验证
python3 verify.py

# 5. 回归测试
node smoke-test-pro.js
node audit-harness-pro.js
node audit-engine.js
node stress-test-pro.js
```

### 加一个指标要同步改的地方

漏任何一处都会导致测试失败或页面与引擎不一致：

1. **`engine.js`** —— `computeMetrics()` 计算逻辑 + return 对象加字段。回撤类指标尽量复用已有的 `peak/maxDD` 遍历，不要重复扫。
2. **`app-pro.html`** —— 三处：`renderMetrics()` 的指标卡数组、`renderCmpTable()` 的表头与单元格、`.notes` 口径说明（**必须写清公式**，这是交付物的可信度依据）。
3. **`run_engine.js`** —— 输出到 `engine_result.json` 的 metrics 字段。
4. **`verify.py`** —— Python 独立实现同一算法，并加进 `main()` 的比对列表。
5. **`smoke-test-pro.js`** / **`audit-harness-pro.js`** —— 卡片数量、列数量、数值一致性断言。

### 运行环境

- Node.js（jsdom 是唯一测试依赖）+ Python 3
- ⚠️ 脚本里**硬编码了绝对路径**（`DIR = "/Users/admin/WorkBuddy/dongliang/etf-rotation-backtest"`），换机器需要改这个常量
- ⚠️ 测试用 jsdom 加载 1.4MB 单文件页，**内存占用不低**：在 8GB 机器上并发跑极易被系统 OOM kill（退出码 137、无任何输出）。对策：**一次只跑一套**，用 `> /tmp/x.txt 2>&1` 重定向而不是管道，长任务放后台

### 两条来自实战的测试原则

1. **不要用 `dispatchAction` 强制重渲染来读交互结果。**
   本项目两次栽在这里：用 `showTip` 强制刷新浮层再读文本，等于**绕过了**"鼠标真的压上去时判定对不对"这一步 —— 缺陷长期存在，测试却一路全绿。凡涉及悬停/点击/拖拽的断言，一律用真实事件（`dispatchEvent(new MouseEvent(...))`）驱动。

2. **写完务必注入故障反向验证。**
   断言必须写**不变量**而非"就是第 X 条"（合成坐标系里像素点未必落在预期的那条上）。改完测试后，故意把修复拆掉，确认用例**会红**，否则等于没测。悬停功能就是用这个方法收敛的：注入 3 种故障，其中"只在判定变化时才派发"这一类**只有沿曲线横向拖动的用例能咬住**。

## 数据来源与更新

行情来自**腾讯行情接口**（`web.ifzq.gtimg.cn`），已通过多源校验：

- **无分红 ETF**（513100 / 518850）：直接取前复权序列，与 Wind 逐点一致（偏差 ≤0.115%）。注意 513100 历史含**份额折算**，必须用前复权。
- **分红 ETF**（510300 / 511260）：腾讯/东财的"前复权"对分红标的采用**等差复权**且除息日落点不精确，存在系统性偏差。因此本项目改为抓**不复权价 + 公告分红记录**，重建**标准等比前复权**（除息日因子仅作用于除息日之前的收盘价）。
- **新分红自动识别**：等差 qfq 与不复权的差值步进量恰为每份分红，刷新时据此发现新分红，再用除息日隔夜跌幅校准日期。

### 数据新鲜度：两层机制

| 层 | 触发 | 行为 |
|---|---|---|
| **页面运行层** | 打开页面时 | 先用现有数据（本地缓存 / 内嵌）秒开；再判断新鲜度，**仅当**"落后于最近交易日"**且**"当天尚未成功更新过"时，后台静默刷新一次。同一天重复打开不再联网。只写内存与浏览器缓存，**不改本地文件** |
| **文件内嵌层** | 盘后定时任务（周一至五 16:30） | 依次跑 `rebuild_data.js` → `build_pro.py` → `run_engine.js` → `verify.py` → `smoke-test-pro.js`，让交付文件的内嵌数据保持最新 |

手动全量刷新：点页面右上角"刷新数据"按钮（成功后自动写入浏览器缓存与页面文件）。

`rebuild_data.js` 的安全闸：每只标的须抓到 ≥500 行、末日不得回退、4 只末日必须一致，任一不通过则**整体放弃不写入**。

## 动手前必读的坑

- **`data.js` 有两条顶层语句**（`var ETF_DATA = {...}` 后面还跟着 `ETF_DATA.extended = {...}`）。任何"读全文件再整体 parse"的写法都会坏：Python 侧用 `JSONDecoder().raw_decode()` 只解析第一条；JS 侧用 `rebuild_data.js` 里的 `splitDataJs()` 按括号深度扫描。
- **`rebuild_data.js` 只改 `data.js`，不生成页面**；无新交易日时会跳过写入，此时不要再继续跑后续构建。
- **`smoke-test-pro.js` 里的 `PRO_OPTS` 必须与网页默认档位一致**（如 `volTarget` 必须是页面默认的 0.18），否则核心指标断言会集体误报。改页面默认参数时记得同步。
- **测试假数据的末日不要硬编码**，按"当天最近交易日"动态算，否则断言会随日期流逝而失效。同理，慎用按旧数据末日标定的魔数阈值。
- **净值图悬停为什么实现得那么绕**：ECharts 的 `emphasis.focus:'series'` 淡出**不派发任何事件**，且 tooltip 的 `formatter` 渲染那一刻元素状态正被改写（读不到焦点）；`getZr().findHover()` 的返回值与 ECharts 真正认的悬停目标**不总是同一个**。最终方案是"**几何自算判定 + 主动 `dispatchAction` 驱动画面**"，判定与画面共用同一变量，结构上不可能分歧。细节见 `需求规格说明书.md` §8.3。
- **`etf_rotation_state.json` 是运行记录**，会被脚本更新；提交前确认它是否属于本次改动。
